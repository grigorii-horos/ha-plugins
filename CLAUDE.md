# CLAUDE.md

Кастомные карточки Lovelace для Home Assistant. Каждая собирает несколько сущностей
одного устройства (или одного смысла) в одну плитку.

## Главное правило

**Переиспользовать компоненты самого HA, а не повторять их вёрстку.** Плитка строится
из `ha-tile-container`, `ha-tile-icon`, `ha-tile-info`, `hui-card-features`,
`ha-ripple`, `state-display`; редакторы — из `ha-form`, `hui-card-features-editor`,
`ha-expansion-panel`. Своим оставлять только то, чего у HA действительно нет.

Своя копия чужой вёрстки отстаёт от оригинала и теряет то, что в компонентах уже
есть: ripple, распознавание жестов, кольцо фокуса, штатные features. Однажды
переписанная на компоненты HA карточка потеряла ~175 строк своего кода вместе с
целым классом заведшихся в нём ошибок.

Компоненты наружу не экспортируются, но регистрируются, когда HA подгружает бандл
штатной плитки. Дёргается это в `core/ha-internals.ts`: `window.loadCardHelpers()` →
`createCardElement({type: "tile"})` ради побочного эффекта импорта, затем
`customElements.whenDefined`.

Второе правило: **карточка не универсальный конструктор**. В конфиге сказано, какая
сущность играет какую роль (`temperature`, `battery`, `cartridges`), а раскладку
карточка выбирает сама. Автоопределение сущностей по имени или device_class не
делаем — роли задаёт человек.

## Команды

```sh
cd cards
npm run dev     # http://<этот-хост>:5188, для правки на живом HA
npm test        # vitest, логика в node + разметка в happy-dom
npm run build   # tsc --noEmit && vite build → ../dist/ha-plugins-cards.js
../script/publish.py   # сборка + заливка на хост HA + обновление ресурса дашборда
```

## Раскладка

- `cards/src/cards/*-tile.ts` — карточки, по одной на файл; каждая наследует
  `BaseTileCard`, объявляет свой `*Config` и в конце вызывает `registerCard`.
- `cards/src/editors/*-tile-editor.ts` — графические редакторы, все через
  `FormCardEditor`/`BaseCardEditor` из `base-editor.ts`.
- `cards/src/core/` — общее: сборка плитки (`base-tile-card.ts`), строки уровней
  (`levels.ts`), форматирование ролей (`format.ts`), цвета состояний
  (`state-color.ts`), действия (`actions.ts`), словари (`i18n.ts`), регистрация
  (`register.ts`).
- `cards/src/main.ts` — точка входа, импортирует всё.
- `dist/ha-plugins-cards.js` — **версионируется намеренно**: HACS ставит плагин
  прямо из репозитория. После правок его нужно пересобрать и закоммитить.
- `docs/images/` — скриншоты для README.
- `docs/superpowers/specs/2026-09-04-ha-tile-cards-design.md` — спека: решения,
  обоснования и список того, чего против штатной плитки нет.
- `frontend/` — клон home-assistant/frontend, только как справочник по вёрстке и
  токенам. Не часть проекта, в git не попадает.

## Соглашения

- Комментарии по-русски и объясняют **почему**, а не что. Строки интерфейса — через
  `t()` из `i18n.ts`, обе локали (ru/en) заполняются сразу, включая формы
  множественного числа.
- Цвета и размеры — только через токены HA с запасным значением:
  `var(--ha-font-size-m, 14px)`. Своих чисел в пикселях не изобретать.
- Новая карточка = карточка + редактор + запись в таблицу README + скриншот.
- Общие поля конфига (`name`, `icon`, `state_content`, `features`, шесть действий)
  живут в `TileBaseConfig`; `setConfig` наследника обязан положить их в `this.base`.

## Проверка результата

Смотреть на свою работу глазами до того, как объявлять её готовой: поднять
`npm run dev`, открыть дашборд и снять скриншот через CDP. Правки вёрстки без
скриншота не считаются проверенными — так были пойманы почти все дефекты в этом
проекте (нечитаемые уровни, невидимые на тёмной теме чернила, серый ripple, промах
мимо цели тапа).

Грабли, на которые уже наступали:

- Дашборд с dev-сервера открывается по **http** — иначе браузер зарубит http-модуль
  как mixed content.
- Обновление только F5: переопределить зарегистрированный custom element нельзя,
  поэтому HMR в `vite.config.ts` выключен.
- Адрес ресурса в дашборде должен нести версию (`?v=<хеш>`), иначе HA отдаёт
  закешированный старый бандл и обновление проходит незаметно.
- Скрипты, трогающие конфиг дашборда, обязаны **сливать** его, а не переписывать: там
  бывают правки, сделанные руками в GUI.
- В скриншоты для README не должны попадать адреса, лица и имена живых людей —
  карточку людей перед съёмкой обезличиваем (`show_entity_picture: false`, без
  `location`).
